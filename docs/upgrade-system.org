#+TITLE: Plan: Upgrade System + Upgrade Menu
#+OPTIONS: ^:{}

* Goal

Turn the shipped modifier machinery into a real progression system: a pan-able
skill tree, rendered in the empty central area of the paused screen, where energy
buys multi-level nodes that scale params, unlock capabilities, and grant content.
Architecture must absorb prestige (Meta scope) and entirely custom mechanics
(gravity wells, energy harnessers) without restructuring.

Decisions are recorded in [[file:adr/0006-upgrade-system.org]]. Vocabulary:
[[file:glossary.org]]. Depends on / amends [[file:adr/0005-modifier-system.org]].

* Decisions (from design interview)

| Question               | Decision                                                                 |
|------------------------+--------------------------------------------------------------------------|
| Ownership of permanent effects | Upgrade *levels* are truth; fold reads them. Upgrades never create Modifiers |
| Level model            | Multi-level, per-node =max_level= (=1 expresses one-shots)                |
| Scope                  | =Upgrade_Scope{Run, Meta}= modelled now; only Run implemented             |
| Effect encoding        | Closed =Upgrade_Id= + effect union: Param (fold) / Capability (bit_set) / Grant (write) |
| Prereqs                | DAG via fixed =requires[MAX_UPGRADE_REQUIRES]= slots with =.None= sentinel |
| Node count             | Unbounded (arrays, not =bit_set=); =bit_set= would cap at 128             |
| Unlock conditions      | Closed =Upgrade_Condition_Kind=; *monotonic metrics only*, no latch state |
| v1 condition kinds     | None, Lifetime_Energy_Earned, Celestial_Discovered, Upgrades_Purchased    |
| Cost curve             | =base_cost * cost_growth^level=, coefficients in =Parameters=             |
| Cost source            | =effective_params.upgrades= (moddable); cost branches exclude their own id |
| Effect math            | Per-node =Upgrade_Op{Add, Mul}= applied =level= times, shared util        |
| Fold order             | Upgrades (enum order) → Modifiers (enum order) → companions recompute     |
| System layout          | =sys_modifier= absorbs upgrades (single derive pass); ops in NEW =upgrades.odin= |
| Paused correctness     | Derive pass runs in =.Paused= too; modifier timers tick only in =.Playing= |
| Capabilities           | =bit_set[Capability]= derived every frame from levels, never persisted    |
| Derived companions     | One recompute step at end of derive pass (supersedes ADR 0005 per-branch) |
| Refunds                | None. Prestige is the only reset                                          |
| Reset seam             | =upgrade_reset(g, scope)=; =game_reset= = all scopes, prestige = Run only |
| Grants after reset     | =upgrade_reapply_grants= re-applies grants of surviving nodes             |
| Menu placement         | Central area of the existing =.Paused= screen. No new Status, no tabs     |
| Navigation             | Single canvas, mouse pan, clamped; zoom deferred                          |
| Coordinates            | Authored canvas =pos= per node; composed into screen-space rects at layout |
| Category               | Per-node visual attribute only (tint + label), never a spatial grouping   |
| Pan vs buy             | LEFT drag pans; buy on release if drag < threshold and cursor still on node |
| Purchase UX            | Immediate click-buy + hover tooltip (no confirm dialog)                   |
| Node states            | Hidden / Silhouette / Locked / Available / Owned / Maxed; two-hop reveal  |
| Affordability          | Not a state; evaluated at render/click time                              |
| Data placement         | Structure in compile-time =UPGRADE_DEFS=; balance in =Parameters.upgrades= (unpersisted) |
| Persistence            | No =SAVE_VERSION= bump (pre-release); count-prefixed levels + lifetime energy |
| Energy mutations       | NEW =economy.odin= (=economy_add_energy= / =economy_try_spend=)           |
| Number formatting      | NEW =utils_format.odin= compact formatter, adopted by menu + top bar      |
| Activatables           | Deferred; debug keys G/H keep the temp-modifier path alive                |
| Layout/hit-test pattern| Control Menu pattern: rects filled during draw, hit-tested in input      |
| Phasing                | 4 phases: engine → menu → wiring → balance/persistence                   |

* Engine

** Ops file — =game/upgrades.odin= (NEW, non-sys)

#+begin_src odin
upgrade_cost            :: proc(g: ^Game, id: Upgrade_Id) -> f64
upgrade_effect_value    :: proc(g: ^Game, id: Upgrade_Id, level: u8) -> f32 // tooltip preview
upgrade_requires_met    :: proc(g: ^Game, id: Upgrade_Id) -> bool
upgrade_condition_met   :: proc(g: ^Game, id: Upgrade_Id) -> bool
upgrade_can_afford      :: proc(g: ^Game, id: Upgrade_Id) -> bool
upgrade_can_purchase    :: proc(g: ^Game, id: Upgrade_Id) -> bool
upgrade_purchase        :: proc(g: ^Game, id: Upgrade_Id) -> bool
upgrade_purchased_count :: proc(g: ^Game) -> int
upgrade_reset           :: proc(g: ^Game, scope: Upgrade_Scope, all: bool = false)
upgrade_reapply_grants  :: proc(g: ^Game)
#+end_src

=upgrade_cost= uses =effective_params.upgrades[id]= and the current level:
=base_cost * cost_growth^level=. Math helper in =utils_math.odin=
(=math_geometric_cost(base, growth, level) -> f64=).

=upgrade_purchase= order of checks (all must pass, no partial mutation):

1. =id != .None=, =UPGRADE_DEFS[id].scope= is implemented (v1: =.Run=).
2. =upgrade_levels[id] < params.upgrades[id].max_level=.
3. =upgrade_requires_met= (all non-=.None= slots have level > 0).
4. =upgrade_condition_met=.
5. =economy_try_spend(g, upgrade_cost(g, id))=.
6. =upgrade_levels[id] += 1=.
7. If effect is =Upgrade_Effect_Grant=: =slingshot.available_objects += {celestial}=.

Failure returns false and logs at debug/warn. Param and Capability effects need
no purchase-time work — the next derive pass picks them up.

=upgrade_reset(g, scope, all)= zeroes matching levels, then calls
=upgrade_reapply_grants= so surviving nodes' grants are restored (relevant once
Meta grants exist). =game_reset= calls it with =all = true= and also zeroes
=lifetime_energy_earned=.

** Derive pass — =game/sys_modifier.odin=

Ordered steps (single procedure, file-private helpers):

1. *Tick + expire temp modifiers* — only when =g.status == .Playing=. Pausing
   must not consume buff duration.
2. =g.effective_params = g.params= (struct copy).
3. *Fold upgrades* — for =id in Upgrade_Id=, skip =.None= and level 0, then a
   switch on =id= applies the node's Param effect via the shared math util.
   Iteration is in enum declaration order, so composition is deterministic.
4. *Fold modifiers* — existing per-kind switch, unchanged (ADR 0005 order).
5. *Recompute derived companions* — =cursor_distance_squared=,
   =world_radius_squared= recomputed from their sources. Single site; new fold
   branches cannot forget it. (Supersedes ADR 0005's per-branch rule.)
6. *Derive capabilities* — clear, then for each node with level > 0 whose effect
   is =Upgrade_Effect_Capability=, add its bit.
7. *Derive node states* — see below.

Cost: one struct copy + a bounded loop over =len(Upgrade_Id)= with a 4-slot
prereq check and a two-hop reveal check. Negligible per frame.

** Shared effect math — =game/utils_math.odin=

#+begin_src odin
math_apply_upgrade_op :: proc(v: f32, op: Upgrade_Op, magnitude: f32, level: u8) -> f32
// Add: v + magnitude * f32(level)
// Mul: v * pow(magnitude, f32(level))
math_geometric_cost   :: proc(base, growth: f64, level: u8) -> f64
#+end_src

Both the fold and the tooltip preview call these, so displayed and applied
values cannot diverge.

** Node state derivation

Per node, with =owned(x) := upgrade_levels[x] > 0=:

#+begin_example
level == max_level                          -> Maxed
level > 0                                   -> Owned
requires_met && condition_met                -> Available
hop_distance == 1                            -> Locked
hop_distance == 2                            -> Silhouette
otherwise                                    -> Hidden
#+end_example

=hop_distance= is 1 if the node has no requires (root) or any direct prereq is
owned; 2 if any prereq-of-prereq is owned; else 3+ (=UPGRADE_MENU_REVEAL_HOPS=
= 2 governs the cutoff). Meta-scope nodes are forced =Hidden= in v1.

Because every input (levels, monotonic metrics) is non-decreasing, a node never
regresses to a less-visible state. Affordability is deliberately excluded so
nodes do not flicker as energy rises and falls.

** Cost-effect self-exclusion

=Research_Grants='s fold branch loops =Upgrade_Id= and multiplies
=effective_params.upgrades[id].base_cost=, *skipping =.Research_Grants= itself*
(and =.None=). Invariant documented in the branch and asserted by a test.

* Upgrade menu

** State — =game/types.odin=

Upgrade_Menu :: struct {

    pan:          rl.Vector2,                 // screen-px offset of the canvas
    framed:       bool,                       // frontier framing applied for this open
    pan_drag:     bool,                       // gesture promoted to a pan

    pan_at_press: rl.Vector2,

** Layout

=viewport= = full screen minus top-bar band and a bottom band reserved for the
future paused-screen action statusbar.

#+begin_example
node_center = viewport_center + def.pos * UPGRADE_NODE_SPACING * g.scale + pan
node_rect   = square of side 2 * UPGRADE_NODE_RADIUS * g.scale centred there
#+end_example

Rects are written into =node_rects= during the draw pass and hit-tested in input
next frame (Control Menu pattern, ADR 0003). Pan is clamped so the tree's
bounding box always overlaps the viewport by at least =UPGRADE_MENU_MARGIN=.

Frontier framing: when =!framed=, compute the bounding box of Owned + Available
nodes (fallback: all non-Hidden nodes), set =pan= to centre it, set
=framed = true=. A =HOME= key press (=.Paused= only) sets =framed = false=;
leaving =.Paused= also clears it so the next open re-frames.

** Rendering — =game/ui_upgrade_menu.odin= (NEW)

Draw order inside the paused overlay (existing dim rectangle stays):

1. Edges: for every visible node, one line per non-=.None= prereq. Edge color by
   state — owned→owned bright, owned→available accent, otherwise dim. Edges to
   =Hidden= nodes are not drawn; edges to =Silhouette= nodes use the dim color.
2. Nodes: circle + category-tinted ring.
   - =Silhouette=: ring only, no text, no cost.
   - =Locked=: greyed fill, name + unmet reason.
   - =Available=: accent ring; cost in compact format; dimmed cost when
     unaffordable.
   - =Owned=: filled, =level/max= pip row.
   - =Maxed=: filled + "MAX", no cost.
3. Hover tooltip card near the cursor (clamped inside the viewport): name,
   category, level =x/max=, current effect value, next-level effect value, cost,
   affordability hint, unmet requirement names, unmet condition text
   (e.g. "Reveal: 25.0K lifetime energy").
4. Header line: total nodes owned, energy on hand (compact), hint text
   ("drag to pan · HOME to recentre").

The existing =ui_top_bar_draw= paused branch (dim + title + PAUSED) is untouched;
=ui_draw= calls =ui_upgrade_menu_draw= when =g.status == .Paused &&
g.help.launch_done=.

** Input

=input_handle_mouse= is restructured to switch on status instead of
early-returning:

#+begin_src odin
switch g.status {
case .Playing: /* existing world/control-menu body */
case .Paused:  ui_upgrade_menu_handle_mouse(g)
case .Exit:
}
#+end_src

Gesture (=ui_upgrade_menu_handle_mouse=, screen-space only):

| Event                       | Behavior                                                                  |
|-----------------------------+---------------------------------------------------------------------------|
| LEFT pressed inside viewport| =press_pos= = mouse, =pan_at_press= = pan, =pressed_node= = node under cursor, =pan_drag= = false |
| LEFT down                   | if =dist(mouse, press_pos) > UPGRADE_MENU_DRAG_THRESHOLD * g.scale= → =pan_drag = true=, =pressed_node = .None=; when panning, =pan = clamp(pan_at_press + (mouse - press_pos))= |
| LEFT released               | if =!pan_drag= and =pressed_node != .None= and cursor still inside that node's rect → =upgrade_purchase=; then clear gesture state |
| mouse move (no button)      | =hover_node= = node under cursor (Hidden/Silhouette nodes are not hoverable) |
| RIGHT pressed               | consumed, no-op (world demolish must not fire while paused)                |

New input action: =.Upgrades_Recenter= = keyboard =HOME=, status =.Paused=,
handled in =input_handle_action= by clearing =framed=.

Clicks on =Silhouette=, =Locked= and =Maxed= nodes are no-ops (tooltip still
explains why). Unaffordable clicks are no-ops.

** Paused-frame ordering

=game_run= =.Paused= branch becomes: =sys_modifier(g)= then =sys_render(g)=.
Purchases made during frame N are visible in =effective_params= from frame N+1;
tooltips read levels directly through =upgrade_effect_value=, so displayed
previews have no lag.

* Persistence

No =SAVE_VERSION= bump (pre-release policy — see AGENTS.md). Local saves from
before this change fail validation and the game starts fresh.

Payload additions:

#+begin_example
score block  : ... existing ..., lifetime_energy_earned f64
tail         : upgrades_count u64 (= len(Upgrade_Id)), then upgrades_count x u8 level
#+end_example

Load rules:

- =upgrades_count > len(Upgrade_Id)= → =r.ok = false= (reject save).
- =upgrades_count < len(Upgrade_Id)= → remaining nodes read as level 0, so
  appending nodes to the enum keeps saves loadable.
- =level > params.upgrades[id].max_level= → clamp to =max_level= + =log.warn=
  (balance may legitimately shrink a cap).
- =Upgrade_Id= ordering is *append-only* by convention: reordering invalidates
  existing saves silently.

Not persisted (derived / transient): =upgrade_states=, =capabilities=,
=effective_params=, =upgrade_menu=. =Parameters.upgrades= stays out of
=persist_write_params= (=emitter_presets= precedent) so balance changes reach
old saves.

* Read-site rules

- Costs, effects and every runtime param read: =g.effective_params=.
- =g.params= remains BASE: written only by =params_init= and load; read by the
  fold, persistence and tests.
- Capability checks read =g.capabilities= (never =upgrade_levels= inline), so
  gate sites do not learn node ids.
- Menu queries go through =upgrades.odin= helpers, never re-deriving cost or
  effect math inline.
